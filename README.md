# Teiko Clinical Trial – Immune Cell Analysis

Analysis pipeline and interactive dashboard for how **miraclib** affects immune cell populations across Loblaw Bio clinical trial samples.

**Chatbot:** [https://teikochat.streamlit.app/](https://teikochat.streamlit.app/) — ask questions about the trial data in plain English.

---

## Quick Start

```bash
make setup      # install dependencies
make pipeline   # build teiko.db + generate outputs/
make dashboard  # Flask server at http://localhost:8080
make test       # run pytest suite
```

## Database Schema

Five normalised tables: `projects → subjects → samples → cell_counts → cell_frequencies`

```
subjects      subject_id PK, project_id FK, condition, age, sex
samples       sample_id PK, subject_id FK, treatment, response, sample_type, time_from_treatment_start
              treatment values: miraclib / phauximab / none*
cell_counts   sample_id PK, b_cell, cd8_t_cell, cd4_t_cell, nk_cell, monocyte
cell_frequencies  (sample_id, population) PK, count, total_count, percentage
```

> *`treatment = 'none'` means placebo/control — not a missing value.

`cell_frequencies` is materialised at load time (52,500 rows = 10,500 samples × 5 populations) so queries never recompute percentages. Indexes on `condition`, `treatment`, `response`, `sample_type`, and `time_from_treatment_start` keep filters fast.

### Why multiple tables?

Subject demographics (condition, age, sex) are stored once in `subjects` — not repeated on every sample row. If a field is corrected, one row changes instead of many. New assay types slot in as new tables keyed on `sample_id` without touching existing tables.

## API Endpoints

All endpoints accept query parameters; the database filters server-side — the browser never receives data it doesn't need.

| Endpoint | Parameters | Returns |
|---|---|---|
| `GET /api/initial-analysis` | condition, treatment, sample_type, time, response, sex, population | Filtered cell-frequency rows |
| `GET /api/initial-analysis/opts` | — | Distinct dropdown values |
| `GET /api/statistical-analysis` | condition, treatment, sample_type | Mann-Whitney U stats + SQL-computed boxplot quartiles |
| `GET /api/data-subset-analysis` | condition, sample_type, time, treatment | Sample/subject counts + avg B-cell for male responders |
| `GET /api/data-subset-analysis/opts` | — | Distinct dropdown values |

## Dashboard Tabs

- **Initial Analysis** – filter by any combination of condition, treatment, sample type, time, response, sex, or population; paginated table + bar chart update per API call.
- **Statistical Analysis** – Mann-Whitney U boxplots for responders vs non-responders; quartiles (Q1, median, Q3), whiskers (1.5 × IQR), and outliers computed in SQL.
- **Data Subset Analysis** – four dropdowns drive live charts (samples per project, subjects by response/sex); avg B-cell for male responders uses condition + time only, independent of sample type and treatment.

### Boxplot whiskers

Whiskers mark the **valid data range**: lowest value ≥ Q1 − 1.5×IQR and highest value ≤ Q3 + 1.5×IQR. Points beyond the whiskers are outliers and plotted individually.

## Statistical Methodology (Part 3)

**Test:** Mann-Whitney U (two-sided) — non-parametric, no normality assumption, robust to outliers.
**Threshold:** α = 0.05 on raw p-values.
**Result:** CD4 T Cell shows the strongest trend (p = 0.0133); no population reaches significance.

**Significance notation:** `ns` p ≥ 0.05 · `*` p < 0.05 · `**` p < 0.01 · `***` p < 0.001

## Tests

```bash
make test   # or: pytest tests/test_data.py -v
```

| Category | What is tested |
|---|---|
| Duplicates | INSERT OR IGNORE idempotency across all tables; `populate_frequencies` called twice |
| Bad data | Non-integer counts (with rollback), blank age/response → NULL, missing columns, empty CSV |
| Correctness | Percentages sum to 100%; known counts produce correct percentage values |

## Limitations

| Area | Current limitation | Path forward |
|---|---|---|
| **Ingestion** | Row-by-row Python loop | Batch `executemany`; PySpark for large files |
| **Database** | SQLite — single writer, no native percentile functions | PostgreSQL / DuckDB; BigQuery for cloud scale |
| **ORM** | Raw SQL strings throughout — no schema validation or migration support | SQLAlchemy ORM: declarative models enforce schema in Python, `Alembic` handles migrations, and the same model layer works across SQLite, PostgreSQL, and other backends without rewriting queries |
| **API** | Flask dev server, single-threaded | Gunicorn (multi-worker) or FastAPI |
| **Row updates** | `INSERT OR IGNORE` silently drops corrections | Upsert with `ON CONFLICT … DO UPDATE` |
| **Statistics** | Two-group Mann-Whitney U only | Mixed-effects models for longitudinal/multi-group analysis |
| **Schema** | No CHECK constraints on cell counts or controlled vocabularies | Add constraints to DDL |
